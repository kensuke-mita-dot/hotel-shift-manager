# 画面仕様（Phase 1）

モック：`prototype/Hotel Shift Mock.dc.html`（1a スタッフ／1b 管理者スマホ案A／1d 管理者PC）

## 共通

- **ヘッダー**：左にアプリ名「HOTEL SHIFT」とログイン中の人（例「高橋 由衣 · BHJ・MAHT」「管理者 · 全施設」）。
- **タブ**：ヘッダーの直下に置く（スマホも上部）。選択中は青文字と下線2px（`#2b8fe0`）。
  - スタッフ：希望入力／確定シフト
  - 管理者：日次調整／月間（Phase 2 で「スタッフ・人件費」「履歴」を追加）
- **管理者の施設切り替え**：タブの下に横スクロールのボタン列。「全施設」BHJ BHKK MAHB MAHT MAHNM の順。
  - 選択中：青の塗りに白文字
  - 欠員とNGの件数を赤い四角の数字で表示（日次調整では当日分、月間では月の合計）
- **ボトムシート**：スマホは下から出し、PCは画面中央（最大幅440px）。背景をタップすると閉じる。
- **トースト**：画面下に黒地・白文字で2.2秒表示。
- **URL**：`/admin/daily?facility=BHJ&date=2026-11-10`、`/admin/monthly?facility=all&month=2026-11` のように、施設・日付をURLに持たせる。

## S1. ログイン `/login`

- メールアドレスの入力欄と「ログイン用リンクを送る」ボタン。
- 送信後の表示：「{メールアドレス} にリンクを送りました。メールのリンクを開くとログインできます。」
- 登録されていないメールアドレスでも、同じ表示にする（登録の有無を知られないため）。
- リンクを開いた後は `/auth/callback` を通り、役割に応じて移動する（管理者→`/admin/daily`、スタッフ→`/staff/requests`）。
- 実装：`supabase.auth.signInWithOtp({ email, options: { shouldCreateUser: false, emailRedirectTo } })`

## S2. スタッフ：希望入力 `/staff/requests`

**対象月**：今日の翌月（本番では、期限前なら翌月、期限後は翌々月を選べると便利。Phase 1 は翌月固定でよい）。

**上部**：小見出し「希望入力 · 提出期限 10/15（木）」。延長されている場合は「→ 延長 10/25（日）まで」を足す。見出しは「2026年11月」。右側に状態タグ。

| 状態 | タグの文言 |
| --- | --- |
| 提出していない | 未提出 |
| 提出済み | 提出済 10/12 22:41 |
| 入力を変えたが未保存 | 未保存の変更あり |

**カレンダー**：7列（日〜土）。日曜は赤、土曜は青。1マスの高さは58px。
- マスの中：日付（左上）、希望の略称（朝／夕／朝夕／夜／休／時間）、時間指定ならその時刻（例 10-16）
- 背景：休はオレンジ系の `#fdf0e6`、それ以外の希望は `#eaf4fd`、空欄は白

**件数**：「朝 n」「夕 n」「朝夕 n」「夜 n」「時間指定 n」「休 n」「空欄 n」。

**日付をタップ** → ボトムシート「希望を選択（施設は管理者が決めます）」。
- 選択肢は横一列に並べる：朝 8-16 ／ 夕 14-22 ／ 朝夕（どちらも可）／ 夜 22-8 ／ 時間指定 ／ 休
  - 朝・夕・夜は、スタッフの所属施設に該当する枠がある場合だけ出す（MAHTだけに所属する人には夜は出さない）。
  - 表示する時刻は、主な所属施設の枠の時刻。
- 時間指定：開始・終了のプルダウン、15分／30分刻みの切り替え、「○時間○分 · 日をまたぐ」の表示、「この時刻で決定」ボタン。
- 「クリア」ボタンで、その日を空欄に戻す。

**提出ボタン**：「保存して提出」（提出済みなら「変更を保存して再提出」）。高さ46px以上、青の塗り。
- 空欄が1日でもあれば、確認のシートを出す。
  - タイトル：「空欄が n日 あります」（小見出し「提出前の確認」）
  - 本文：「空欄の日は「希望なし」として提出されます。勤務の可否は管理者が判断し、休みになる場合もあります。このまま提出してよいですか？」
  - 空欄の日付をチップで並べる（例「12日（木）」）。タップするとその日の選択シートに移る。
  - ボタン：「戻って入力する」（白）、「空欄のまま提出」（青）
- 空欄がなければ、確認なしで提出する。トースト「希望を提出しました」。

**期限後**（延長も過ぎた場合）：赤い枠で「提出期限を過ぎたため変更できません。変更が必要な場合は、管理者に期限の延長を依頼してください。」と表示する。マスをタップしても開かず、トーストで同じ内容を出す。提出ボタンは無効にする。

**保存方式**：その月の希望を全件 upsert し、空欄になった日は delete する。そのあと `submit_requests(month)` を呼んで提出日時を記録する。

## S3. スタッフ：確定シフト `/staff/schedule`

- 兼任している人は、上部の施設ボタンで所属施設を切り替える。
- 小見出し「BHJ · 確定シフト · 閲覧のみ」。右側に「あなた（全施設）：n日 · n.nh」。
- **表**：スタッフ×日付（1〜末日）。施設に所属するスタッフ全員を表示する。
  - 左の名前列（幅76px）と日付の行は、スクロールしても固定する。
  - 1マスは幅44px・高さ34px。罫線を含めて日付の列とそろえる（`box-sizing:border-box`）。
  - 自分の行は薄い青の背景にし、名前を太字にする。
  - マスの中は、小さな角丸チップで表示する（幅36px）。
    - 勤務：グレーのチップに白文字（朝／夕／夜／基本／時刻）
    - 休み：オレンジ系のチップに「休」
    - 他の施設で勤務：白地に灰色の文字で施設名（例 MAHT）
    - NGがあるとき：チップを赤にする
- 表示するのは `published_shifts`（公開版）だけ。
- 下に凡例：自分の行／施設名＝その施設で勤務／NG（インターバル・重複）。

## S4. 管理者：日次調整 `/admin/daily`（案A）

### 施設を選んでいるとき

**日付の切り替え**：左右の矢印ボタン（44×44px）と、中央に「11月10日（火）」。その下に状態を1行で表示する。
- 例：「BHJ · 欠員 1枠 · NG 2件 · 未確定 3件」
- 問題がなければ「問題なし · 確定済み」
- 欠員やNGがあるときは赤文字

**操作の補助**：「AI下書き作成」ボタン（無効・「近日公開」タグ付き）と、説明文「カードを長押しでドラッグ／タップで編集」（PCでは「カードをドラッグで枠へ／クリックで時刻編集」）。

**枠のカード**（施設の枠の数だけ縦に並べる。MAHTは1枚）
- 見出し：枠名（朝）、時刻（08:00–16:00、夜は 22:00–翌08:00）。右に「配置/最低」と、−／＋の付いた「2/1名」。
  - −／＋はその日だけの最低人数を変える。その場合は「配置/最低（この日のみ）」をオレンジ文字で表示する。
- 人数が足りないとき：枠を赤系にし、「欠員：最低1名の配置が必要です」または「あと1名必要です（最低2名）」と出す。
- 配置されたスタッフはチップで並べる（高さ44px、グレー地に白文字）。チップには次を出す。
  - 時間指定なら、その時刻
  - 枠の一部しかカバーしない場合は「一部」
  - NGなら赤地にし、「NG インターバル」または「NG 重複」と表示
  - 未確定なら小さな青い点
- 末尾に「＋ 追加」（点線の枠）。

**スタッフ一覧**（スマホは画面下に固定した横スクロール、PCは右側に幅340pxの列）
- 見出し「未配置スタッフ n名」
- 各スタッフ：名前、希望バッジ（朝／夕／朝夕／夜／休／時刻／—）、配置の状態
  - 配置の状態は「→ 朝」「未配置」「MAHT 基本」のいずれか。最後は他の施設に配置済みの場合で、オレンジ文字にする。
- 並び順：未配置の人を上に、配置済みの人は薄く表示する。
- 一覧の上にドロップすると「配置を外す」。

**操作**
- **長押し（380ms）でドラッグ**（タッチ操作の場合）。マウスの場合は5px動かすと開始。
  - ドラッグ中は、指の上に「佐藤 美咲 → 朝の枠」の吹き出しを出す。重なっている枠は青枠・青背景にする。
  - 指を離すと、その枠に配置する（同じ施設・同じ日にすでに配置があれば置き換える）。
- **タップ**で、スタッフのシートを開く。
  - 小見出し「BHJ · 11月10日 · 現在 朝」、タイトルはスタッフ名、右上に希望バッジ。
  - 選択肢：枠の数だけ並べ、続けて「時間指定」「外す」。
  - 他の施設にも配置されていれば、オレンジの枠で「この日は MAHT 10:00–18:00 にも配置されています」。
  - 選んだ内容でNGになる場合は、配置する前に赤い枠で知らせる。例：「インターバル 2時間：BHJ 15日 22:00–翌08:00 → MAHT 16日 10:00–18:00（8時間以上必要）。保存はできます。」
- **「＋ 追加」**で、候補者のシートを開く。
  - 並び順：希望が一致して未配置の人 → 未配置の人 → 配置済みの人
  - 各行に希望バッジと現在の配置を表示する。

**保存**：操作するたびにすぐ保存する（`status='draft'`）。

### 「全施設」を選んでいるとき

- 日付の切り替えは同じ。状態の行は「全施設 · 欠員 n枠 · NG n件 · 未確定 n件」。
- 施設ごとのカードを並べる（PCは格子状、最小幅300px）。
  - 施設名、「出勤 n／n名」、右上の状態（「欠員1・NG2」は赤地、「問題なし」は青系）
  - 枠ごとの小さな箱：枠名、「1/1名」、配置された人の姓（欠員なら「欠員」と赤文字）
  - 下の行：「未確定 n件」または「確定済み」と、「この施設を調整 →」
- カードをタップすると、その施設の日次調整に移る。

## S5. 管理者：月間 `/admin/monthly`

### 施設を選んでいるとき

- 小見出し「BHJ · 月間マトリックス · 日付タップで日次調整へ」。右上に「確定して公開（未確定 n件）」ボタン。未確定がなければ無効にし、「すべて確定済み」と表示する。
- 表は S3 と同じ形で、下書き（`shifts`）を表示する。未確定のマスは下に青線3pxを引く。
- 表の下に、枠ごとの配置数の行（「朝 配置数」など）。最低人数に足りない日は赤くする。
- 日付の見出しをタップすると、その日の日次調整に移る。
- **確定して公開**：`publish_shifts(facility, month)` を呼ぶ。
  - トースト「確定しました · n名にメールで通知」
  - 公開版との差分があるスタッフにメールを送る（S7）。

### 「全施設」を選んでいるとき

- 施設×日付の表。マスには「欠員の枠の数＋NGの件数」を赤い数字で、問題がなければ「○」を薄い灰色で表示する。
- 施設名をタップするとその施設の月間に、日付をタップすると全施設の日次調整に移る。
- 「全施設を確定して公開（未確定 n件）」ボタン。

## S6. 管理者：スタッフ `/admin/staff`（Phase 1 は最小限）

- 一覧の項目：名前、メールアドレス、所属施設（主な所属に「（主）」）、11月分の提出状況（未提出は赤文字）、延長の状態。
- **招待**：名前・メールアドレス・所属施設（複数選択）・主な所属を入力する。既存の `inviteStaff` を拡張して使う。
- **所属の変更**：施設の追加・削除、主な所属の変更。
- **期限の延長**：ボタン「期限を延長」で日付を選ぶ（初期値は今日から7日後）。延長中は「延長を取り消す」を表示する。トースト「{名前}さんの期限を10/27（火）まで延長し、メールで通知しました」。
- **停止**：退職者はログインできないようにする（`profiles.is_active=false`）。削除はしない。
- 時給・交通費の入力欄は Phase 2 で追加する。DBの列は Phase 1 から用意しておく。

## S7. メール通知

| いつ | 宛先 | 件名 | 本文の要点 |
| --- | --- | --- | --- |
| 確定して公開 | 公開版との差分があるスタッフ | 【シフト確定】2026年11月（BHJ） | 確定したことと、自分の勤務日の一覧、アプリへのリンク |
| 確定後に再公開して変わったとき | 変更があった本人 | 【シフト変更】11/10 BHJ | 変更前→変更後、アプリへのリンク |
| 期限の延長 | 対象のスタッフ | 【提出期限の延長】11月分 | 新しい期限、アプリへのリンク |

送信は Server Action から nodemailer で行う（環境変数 SMTP_HOST / SMTP_PORT / SMTP_USER / SMTP_PASS / MAIL_FROM。当面は Google Workspace の SMTP）。送信処理は `src/lib/mail.ts` にまとめ、将来 Resend などに替えやすくする。失敗しても確定処理は取り消さず、画面に「メールの送信に失敗した人：…」と出す。

## チェックの仕様（`src/lib/rules.ts`）

`prototype/shift-data.js` の `violations()`／`checkCandidate()` と同じ結果にすること。

- 各シフトを「対象月1日0時からの分数」で、開始と終了の区間に直す（日をまたぐ場合は終了に1440分を足す）。前月末・翌月初の勤務もデータとして読み込み、境目でも判定する。
- スタッフごとに開始時刻の順に並べ、すべての組み合わせを比べる。
  - 区間が重なる → 重複（両方のシフトに付ける）
  - 前の勤務の終了から次の勤務の開始までが480分未満 → インターバル（両方のシフトに付ける）
- 欠員：その施設・日付で、枠の区間と重なるシフトの数が `min_for(facility, date, slot)` より少ない。
