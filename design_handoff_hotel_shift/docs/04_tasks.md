# 実装の手順とタスク分割

## スケジュールの前提（2026-10-26 時点）

- **11月中**：今までどおり oplus で運用する（11月分のシフトは oplus）。
- **12月分から新アプリで運用**：12月分の希望募集（〜11/15締め）から新アプリを使う。
- 新アプリでの最初の流れ：
  1. 11/1 ごろ、スタッフに案内してログインしてもらう
  2. 〜11/15、希望を提出してもらう
  3. 〜11/25 ごろ、管理者が調整して確定・公開する
  4. 12/1、運用を開始する

そのため、**スタッフ側の機能（ログイン・希望入力）を先に本番公開**し、管理者側の機能（調整・確定）はそのあと2週間で仕上げます。

| 区切り | 期限 | 本番で使えるようにするもの |
| --- | --- | --- |
| **リリース1** | **10/31（土）** | ログイン、希望入力、スタッフの招待、提出状況の確認、期限の延長 |
| **リリース2** | **11/16（月）** | 日次調整（案A）、全施設の一覧、月間表 |
| **リリース3** | **11/20（金）** | 確定して公開、メール通知、スタッフ側の確定シフト閲覧 |
| 予備 | 11/21〜11/25 | 実際の12月分を使って調整・確定 |

リリース1は約1週間しかありません。間に合わない場合は、11/2〜11/3 にずらして、提出期限を延長（11/15 → 11/18 など）します。

## リリース1（〜10/31）：スタッフが希望を出せる

**タスク0　環境の準備**（人の作業。手順は `05_setup_guide.md`。一緒に進めます）
- Supabase：本番用プロジェクトを新しく作る（東京リージョン）
- Vercel：GitHub と連携し、自動で公開されるようにする
- メール：Google Workspace のアプリ パスワードを作り、Supabase の Custom SMTP と Vercel の環境変数に設定する

**タスク1　古いコードの削除とDBの作り直し**
- 削除するもの（使わない・古い）：
  - `src/lib/validation.ts`（夜勤明けNG。rules.ts に置き換え）
  - `src/app/actions/shifts.ts` の `saveShifts`／`fetchDayData`／`fetchMonthData`（作り直し）
  - `src/components/staff/WishInputGrid.tsx`、`src/components/admin/SlotDropZone.tsx`、`StaffPool.tsx`、`MonthlyMatrix.tsx`（作り直し）
  - `src/app/api/shifts/route.ts`、`src/app/api/wishes/route.ts`（Server Actions に統一）
  - `fetch_manga_info.py`、`build_output_csv.py`、`manga_tools_README.md`（このアプリとは関係のないファイル）
  - README の古いセットアップ手順（新しい手順に書き換え）
- 残すもの：`src/lib/supabase*.ts`、`src/middleware.ts`（書き換えて使う）、shadcn/ui の部品、AI下書き関連（Phase 2 用。ボタンは無効表示）
- `003_v2_schema.sql` を migrations に追加し、本番用プロジェクトに 001 → 002 → 003 の順で流す。
- `src/types/index.ts` を新しいスキーマに合わせて書き直す。

**タスク2　ログインの変更**（S1）
- メールのリンクでログインする方式に変える。役割に応じて移動させる。停止中の人はログアウトさせる。

**タスク3　共通のレイアウトとデザイントークン**
- ヘッダー、上部タブ、ボトムシート、トースト。

**タスク4　希望入力**（S2）
- 朝・夕・朝夕・夜・時間指定・休。空欄のまま提出してよく、提出前に確認シートを出す。期限後はロックする。

**タスク5　スタッフ管理の最小限**（S6）
- 招待、所属施設と主な所属、提出状況の一覧、期限の延長、停止。

**10/31 にやること**（人の作業）
- 管理者のアカウントでスタッフ27名を招待する。
- スタッフへの案内を配る（使い方の1枚資料）。
