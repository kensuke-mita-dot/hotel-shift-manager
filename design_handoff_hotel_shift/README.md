# 引き継ぎ資料：ホテル シフト管理アプリ（Phase 1）

対象リポジトリ：`kensuke-mita-dot/hotel-shift-manager`（main）
作成：2026-10-26　／　**12月分のシフトから新アプリで運用**（5施設同時。12月分の希望募集〜11/15締めから新アプリを使う。11月中は oplus と並行）

---

## 1. この資料について

このフォルダは、Claude Code で実装を進めるための引き継ぎ一式です。

- `prototype/` の HTML は**デザインと動きの見本**です。そのままは使わず、既存リポジトリの構成（Next.js 14 App Router ＋ Tailwind ＋ shadcn/ui ＋ Supabase）で作り直してください。
- `prototype/shift-data.js` には、チェックや計算のロジック（インターバル、重複、希望採用率、給与）がまとまっています。**ロジックの正解の見本**として、TypeScript に移植してください。
- 業務ルールの根拠は `docs/requirements.md`（要件定義 v0.2）です。

## 2. 忠実度

**画面構成・操作・文言は高忠実度**で、モックのとおりに作ってください。色と文字は「8. デザイントークン」の値を Tailwind の設定に登録して使います。細かい余白は shadcn/ui の標準に合わせて構いません。

## 5. 既存リポジトリとの差分（要点）

既存コードは「1施設・朝夕夜固定・夜勤明けNG」前提です。主な変更点は次のとおりです。

| 項目 | 既存 | 変更後 |
| --- | --- | --- |
| 施設 | なし | `facilities` と `staff_facilities`（兼任・主な所属） |
| 枠 | enum `shift_slot` 固定 | 施設ごとの `facility_slots`（MAHTは1枠） |
| シフト | `slot` のみ | `start_time`／`end_time` を必ず持つ。時間指定（`custom`）にも対応 |
| 希望 | 朝・夕・夜・休 | 朝・夕・**朝夕**・夜・時間指定・休。**行なし＝空欄** |
| 確定 | `is_confirmed` | 下書きの `shifts` と、公開版の `published_shifts` に分ける |
| チェック | 夜勤明けの朝勤NG | **インターバル8時間未満**と**重複**（施設をまたいで判定） |
| ログイン | メール＋パスワード | **メールリンク**（パスワードなし） |
| 保存 | 1日分を全削除→再挿入 | 1件ずつ upsert／delete（変更履歴を正しく残すため） |

古いコードや使わないファイルは**削除してよい**ことになっています（対象の一覧は `docs/04_tasks.md` のタスク1）。AI下書き関連（`aiDraft.ts`、`ai_draft_runs`）だけは Phase 2 用に残し、Phase 1 ではボタンを無効表示にします。

## 9. モックの開き方

`prototype/Hotel Shift Mock.dc.html` をこのデザインプロジェクト上で開くと、4つの画面（スタッフ・スマホ、管理者・スマホ案A／案B、管理者・PC）を操作できます。単体のファイルとして開いた場合は、一部の見た目が崩れることがあります。
